## 3. 状态管理（Riverpod）

```
providers/
├── serverConfigProvider     # IP:端口 (SharedPreferences持久化)
├── syncStatusProvider       # idle/syncing/offline/error
├── subjectsProvider         # 本地库科目列表+聚合进度
├── chapterProvider(sid)     # 某科目章节
├── quizSessionProvider(cid) # 当前刷题会话：题目队列/当前题/作答/判分结果
├── wrongBookProvider        # 错题流
└── favoriteProvider         # 收藏流
```

原则：UI层只读provider+发事件；所有写库操作收敛到 services 层。

## 4. 本地数据库（sqflite，与PC同构）

```sql
-- subjects / chapters / questions 三表结构与PC端一致（全量同步覆盖写入）
-- questions.material 字段同样保留（QuizScreen先渲染material再渲染stem）

CREATE TABLE local_progress (
    question_id INTEGER PRIMARY KEY,
    is_correct BOOLEAN,
    answered_at TIMESTAMP,
    in_wrong_book BOOLEAN DEFAULT FALSE,
    in_favorites BOOLEAN DEFAULT FALSE,
    sync_status TEXT DEFAULT 'pending'
        CHECK(sync_status IN ('synced','pending','conflict'))
);

CREATE TABLE sync_queue (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    question_id INTEGER NOT NULL,
    action TEXT NOT NULL CHECK(action IN ('answer','wrong_book','favorite')),
    payload TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

判分逻辑（本地执行）：
- single: 所选下标 == answer字母对应下标
- multiple: 所选集合 == answer展开集合（顺序无关）
- judgment: √=true ×=false
- blank: 逐空比对；空内按`;`拆多个可接受答案任一命中即对；忽略首尾空白

## 5. 同步服务（sync_service.dart）

```
首次启动/绑定成功
  → GET /api/sync/all (gzip)
  → 覆盖写入本地三表 → local_progress.sync_status='synced'

日常答题（完全离线可用）
  → 写 local_progress(pending) + 入 sync_queue

检测到局域网可达（App启动/切前台时探测health）
  → 批量 POST /api/sync/progress(queue)
  → 成功：清队列置synced；失败：保留重试

冲突策略：同题两端都有记录取最新时间戳；PC已删题→App静默删；
         schema_version不兼容→提示强制全量刷新
```
