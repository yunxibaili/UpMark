## 2. MD 解析器（strict_parser.py — 核心中的核心）

### 2.1 三原则
- **白名单制**：只认《MD格式规范v2.0》定义的语法，其余行走预定义E/W规则码
- **行级精确**：任何异常必报 文件名+行号+原因码
- **状态机驱动**：逐行扫描，绝无猜测分支，绝不静默丢弃

### 2.2 状态机与匹配优先级

```python
class ParseState(Enum):
    PREAMBLE; CHAPTER; SECTION; QUESTION; MATERIAL; CODE_BLOCK
```

每行处理顺序：
1. 围栏检测优先（CODE_BLOCK态只认```闭合，G7）
2. `# ` H1章节标题
3. `## <序号>、<类型><注记>` 分区头 → 白名单判定（入库型/跳过型W205）
4. `【材料】` 材料块开启
5. 题干起始三样式：`N. ` / `### N. ` / `**题目N**[ [难度]]`
6. 选项行 / 答案讲解行（加粗与非加粗形态）
7. 其他 → 按当前状态归档或W314忽略

预处理：CRLF→LF 归一化；UTF-8无BOM校验(E100)。

### 2.3 校验处置表（完整码表见规范v2.0第八节）

| 情形 | 码 | 处置 |
|------|-----|------|
| 非UTF-8/含BOM、围栏不配对、最终0题 | E100/E122/E130 | 拒整个文件 |
| 简答/计算/论述等主观分区 | W205 | 整区跳过，记录起止行 |
| 缺选项/缺答案/答案非法/无空位等 | W301~W307 | 跳该题并入报告 |
| 缺讲解(W312)/题号断档(W310)/混样式(W311)等 | W3xx | 自动修复保留题目 |

### 2.4 输出物

解析器产出两样东西（结构定义见规范v2.0第十节JSON Schema）：
1. 结构化题目数组 → 入库
2. 导入报告 report_json → 存 import_logs + 返回给管理页/App展示

## 3. 数据库（SQLAlchemy模型 ↔ SQLite主库）

```sql
CREATE TABLE subjects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    folder_path TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP);

CREATE TABLE chapters (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id INTEGER NOT NULL REFERENCES subjects(id) ON DELETE CASCADE,
    title TEXT NOT NULL,
    order_num INTEGER NOT NULL,
    knowledge_md TEXT,                      -- 知识点原始Markdown
    UNIQUE(subject_id, order_num));

CREATE TABLE questions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    chapter_id INTEGER NOT NULL REFERENCES chapters(id) ON DELETE CASCADE,
    type TEXT NOT NULL CHECK(type IN ('single_choice','multiple_choice','judgment','fill_blank')),
    number INTEGER NOT NULL,                -- 章内原始题号
    global_seq INTEGER NOT NULL,            -- W310重排后的连续序号
    material TEXT,                          -- 【材料】块原文(v2.0)，无则NULL
    stem TEXT NOT NULL,
    options TEXT,                           -- JSON纯内容数组，不带"A."前缀
    answer TEXT NOT NULL,                   -- single:"B" multiple:"ABD" judgment:"T"/"F"
    explanation TEXT NOT NULL DEFAULT '',   -- W312允许空串
    source_line INTEGER,                    -- 源文件行号回溯用
    UNIQUE(chapter_id, global_seq));

CREATE TABLE answer_records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    question_id INTEGER NOT NULL REFERENCES questions(id),
    is_correct BOOLEAN NOT NULL,
    answered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    in_wrong_book BOOLEAN DEFAULT FALSE,
    in_favorites BOOLEAN DEFAULT FALSE);

CREATE TABLE import_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id INTEGER,
    file_path TEXT NOT NULL,
    status TEXT NOT NULL CHECK(status IN ('success','partial','failed')),
    report_json TEXT,                       -- 完整导入报告明细
    imported_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP);
```

重复导入策略：同科目同章按 global_seq 覆盖更新。

## 4. REST API

```
GET  /api/health                    → {"status":"ok"}           # App绑定探测
GET  /api/sync/all                  → 全量包(gzip, 含schema_version)
GET  /api/sync/chapters/{sid}       → 章节+知识点
GET  /api/sync/questions/{cid}      → 某章题目

POST /api/sync/progress             ← App批量上报答题记录
POST /api/admin/import              ← 导入文件/文件夹 → 即返report_json
GET  /api/admin/import/{log_id}     ← 历史报告查询
GET  /api/admin/stats               ← 题库统计
GET  /api/admin/template            ← 官方MD模板 + AI提示词模板下载
```

管理网页（FastAPI挂静态页即可）：上传导入、报告可视化、报告一键复制（供回喂AI修复）、模板下载。

## 5. 部署运行

### start.bat（Windows一键启动）
```batch
@echo off
cd /d "%~dp0"
echo 正在启动升本通服务端...
python -m venv venv
call venv\Scripts\activate.bat
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
echo 服务已启动，手机App绑定本机IP:8000
pause
```

```
